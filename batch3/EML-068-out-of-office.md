# Automatic Replies (Out-of-Office) Not Working

**Category:** Email > Automatic Replies
**Article Code:** EML-068
**Tier:** 1
**Audience:** Administrators / Technicians
**Estimated Resolution Time:** 15–30 minutes

## Symptoms / When to Use
- A user enabled Automatic Replies in Outlook or Outlook on the web, but senders never receive them.
- Internal (same-tenant) replies work, but **external** senders get nothing.
- Replies stopped after a scheduled window, or fire outside the intended dates.
- A shared or resource mailbox does not send Automatic Replies.
- Message trace shows a `Drop` event or no reply message is generated at all.

## Background
Microsoft 365 sends one Automatic Reply (OOF) per sender per enabled period — not one per message. Two independent layers must agree for a reply to leave the tenant:

1. **Mailbox layer** — the per-mailbox `AutoReplyState`, message text, audience, and start/end times set by the user or an admin.
2. **Remote domain layer** — tenant-wide policy (`AllowedOOFType`, `AutoReplyEnabled`) that can silently suppress replies to external domains. Remote domain settings **override** the mailbox setting, so a mailbox can be correctly configured yet still send nothing externally.

External-reply failures are almost always the remote domain layer. Internal-only failures are usually the mailbox layer or a Scheduled window that has expired. Note that if an inbound message is classified as spam and routed to Junk, no OOF is generated by design.

## Resolution

### Step 1: Connect to Exchange Online PowerShell
```powershell
Connect-ExchangeOnline -UserPrincipalName admin@yourtenant.com
```

### Step 2: Verify the mailbox configuration
Confirm the state, audience, and schedule. `AutoReplyState` must be `Enabled` or `Scheduled`; if `Scheduled`, the current time must fall between `StartTime` and `EndTime`.
```powershell
Get-MailboxAutoReplyConfiguration -Identity user@yourtenant.com |
    Format-List AutoReplyState,ExternalAudience,StartTime,EndTime,InternalMessage,ExternalMessage
```
- `ExternalAudience: None` means external senders get **no** reply. Set to `Known` (contacts only) or `All`.
- If `AutoReplyState` is `Disabled`, the feature is off.

### Step 3: Set or correct the mailbox configuration
Enable replies with both audiences (admin action on behalf of the user):
```powershell
Set-MailboxAutoReplyConfiguration -Identity user@yourtenant.com `
    -AutoReplyState Enabled `
    -ExternalAudience All `
    -InternalMessage "I am out of office and will reply on my return." `
    -ExternalMessage "Thank you for your email. I am currently out of office."
```
For a scheduled window, use `-AutoReplyState Scheduled` with `-StartTime` and `-EndTime`:
```powershell
Set-MailboxAutoReplyConfiguration -Identity user@yourtenant.com `
    -AutoReplyState Scheduled `
    -StartTime "2026-07-10 08:00:00" -EndTime "2026-07-17 17:00:00"
```

### Step 4: Check the remote domain policy (external replies)
```powershell
Get-RemoteDomain | Format-Table -AutoSize Name,DomainName,AllowedOOFType,AutoReplyEnabled
```
`AllowedOOFType` valid values are `External`, `ExternalLegacy`, `InternalLegacy`, and `None`. If the matching domain (or the `Default` `*` domain) shows `None`, external OOF replies are blocked.

### Step 5: Fix the remote domain policy
Allow external Automatic Replies on the default remote domain:
```powershell
Set-RemoteDomain -Identity Default -AllowedOOFType External -AutoReplyEnabled $true
```
A more specific remote domain entry overrides `Default`. If a per-domain entry (e.g. `contoso.com`) exists, apply the change to that entry instead:
```powershell
Set-RemoteDomain -Identity Contoso -AllowedOOFType External -AutoReplyEnabled $true
```

### Step 6: Test
From an external mailbox, send a message to the user. Confirm a single reply is received. Re-testing from the same sender within the enabled period will **not** produce a second reply — use a different sender or disable and re-enable to reset.

## Troubleshooting
- **No reply at all, internal or external:** Confirm the mailbox has an Exchange Online license and the message was not delivered to Junk. Spam-filtered mail never triggers OOF.
- **Portal alternative:** Set replies via **EAC > Recipients > Mailboxes >** *mailbox* **> Others > Manage automatic replies**, or **Microsoft 365 admin center > Users > Active users >** *user* **> Mail > Automatic replies**. Remote domains live under **EAC > Mail flow > Remote domains**.
- **Reply sent only once:** Expected behavior. OOF fires once per sender per enabled session, not per message.
- **`Drop` event in message trace** (`RESOLVER.OOF.IntToExt` / `ExtToInt`): Normal. Exchange generates both internal and external replies and drops the one that does not apply to the recipient.
- **Hybrid tenants:** For on-premises mailboxes, internal OOF requires `AllowedOOFType InternalLegacy`. `External` alone sends external replies only.
- **Shared mailbox:** Set Automatic Replies with `Set-MailboxAutoReplyConfiguration` against the shared mailbox identity; users cannot always set these from Outlook.
- **Transport rule interference:** Check **Mail flow > Rules** for rules that redirect, block, or delete auto-generated mail.

## Prevention
- Standardize the `Default` remote domain on `AllowedOOFType External` and `AutoReplyEnabled $true` unless a security policy requires suppression.
- Document any per-domain remote domain overrides — they silently supersede the default.
- For planned leave, prefer `-AutoReplyState Scheduled` with explicit start/end times so replies self-disable.
- Include both `-InternalMessage` and `-ExternalMessage` so no audience is left blank.
